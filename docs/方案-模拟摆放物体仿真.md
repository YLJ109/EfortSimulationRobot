# 方案 · 模拟摆放物体仿真（3D 沙盒）

## 一、需求与范围

为系统新增一套 **纯前端 3D 模拟摆放物体** 功能，用于在三维场景里可视化"颜色分拣"这段程序的完整动作。它**不接真机、不驱动真实机器人、不接相机**，全部在浏览器内用 Three.js 模拟完成。

覆盖的动作流程（也是分拣程序 color_sort 的语义）：

```
移动取料 → 吸气 → 移动检测 → 拍照识别颜色 → 按颜色放位 → 放气放下 → 结束
```

这套方案把流程落到三类可交互的 3D 资产上：

1. **供料盒（3×3 源盒）**：放 9 个物体，3 红 + 3 绿 + 3 蓝。
2. **放置盒（目标盒）**：空盒，按"第 1 排红 / 第 2 排绿 / 第 3 排蓝"的顺序承接摆放。
3. **摄像头点位**：一个带标识的检测位，物体在识别时"由黑色变成本色"，并可见照片占位与置信度。

同时满足用户反复强调的四条硬约束：

- 9 个物体**初始全黑**，摄像头识别后才按识别颜色显现。
- 机器人（末端）与物体**发生碰撞吸附**：吸气把物体带走、放气把物体放下。
- 物体可被**点击选中、添加、删除、移动、调大小**，且**不能穿透、可碰撞检测**。
- 数量**可多可少**（循环直到取料区无料，或指定目标个数）。

## 二、坐标系与场景布局

沿用 `three/cell.js` 的世界坐标：Y 轴向上、地板平面 y=0、机器人站台台面 y=0.18、工位约 3.6m 见方，机器人基座位于原点 (0, 0)。

布局采用三处命名点位（用常量集中定义，便于在面板微调）：

| 资产 | 中心坐标（估算，可调） | 说明 |
| --- | --- | --- |
| 源盒（供料 3×3） | (−0.85, 1.15) | 3×3 凹槽托盘，内装 9 物体，初始黑色 |
| 目标盒（放置） | (0.85, 1.15) | 3×3（或更大网格）空托盘 |
| 摄像头点位 | (−1.35, 1.05, 1.65) | 悬空视锥标记，一键切换相机视角至此 |

两个托盘放在机器人正前方、相机默认视角的覆盖范围内；摄像头点位悬于源盒上空以贴合"去检测、拍照、识别"的语义。

## 三、数据模型与状态机

每个物体是一个对象，记录"隐藏真色"和"当前显示色"两套信息：

```js
{
  id,                        // 唯一编号
  colorTrue: "red"|"green"|"blue",   // 真实颜色（隐藏）
  revealed: false,          // 摄像头识别后置 true；false 时显示黑色
  size: {w, h, d},          // 尺寸
  pos: {x, y, z},           // 中心坐标（y 起算于地板，物体底边 ≥ 0）
  mesh,                     // 对应网格
}
```

物体处于三种**搬运状态**之一：

- `IDLE`：静置在托盘或地面，可被自由拖拽/编辑。
- `HELD`：被末端吸气吸附，每帧跟随 TCP 走。
- `PLACED`：放气放下后落回托盘/地面，恢复 `IDLE` 静置。

颜色状态独立于搬运状态：`revealed=false → 黑色`，识别后切到 `colorTrue` 对应的材质。

## 四、视觉与交互设计

### 4.1 视觉

- 物体用圆角立方体，量级约 0.12m；黑色用哑光深灰，显露后红/绿/蓝用纯度较高的材质，选中态叠加自发光描边。
- 源盒/目标盒用低矮带壁托盘，壁高约 0.03m，用半透明材质显示 3×3 格子线，方便看清"哪格已被占用"。
- 摄像头点位用一个小视锥 + "摄像头"标签，点击跳转视角。

### 4.2 交互（作用在 3D 画面）

- **拾取**：对画布做 Raycaster，命中物体即选中（高亮描边 + 侧栏显示编辑项）。
- **拖拽移动**：选中后拖动画布在"地面平面"上平移（Raycaster 打在 y=0 平面取 x/z）。拖拽期间**临时禁用 OrbitControls**，松手恢复，避免视角被拖走。
- **调大小**：侧栏三个滑杆（宽/高/深），改完实时更新网格与碰撞盒。
- **添加/删除**：侧栏"新增物体"按钮（在当前选中位附近空处放一个黑色物体）；"删除选中"移除。

## 五、碰撞与防穿透

物体之间、物体与地板/托盘统一用 **AABB** 判定，量级仅 9 个，性能无压力。

- **地板**：拖拽时强制 `bottom = pos.y − h/2 ≥ 0`。
- **物体互斥**：拖拽中与任一其他物体 AABB 重叠时，把拖拽物体沿最小穿透轴推出，保证永不重叠。
- **托盘**：不与托盘壁体交错——当物体底面落在托盘底板上方时，允许它在格子内移动，但不得穿出外壁。

碰撞逻辑收敛成一个纯函数 `resolveCollision(obj, others)`，便于单测（对应 `tools/` 守卫）。

## 六、动态机制（核心）

### 6.1 吸气跟随 / 放气放下

在 `manager.renderFrame()` 每帧追加 `simObjects.tick()`：

- 当存在"吸气"标记且末端 TCP 与某 `IDLE` 物体中心的三维距离 < 阈值时，该物体置为 `HELD`。
- `HELD` 物体每帧把位置对齐到 TCP 世界坐标正下方（保持直立，y = 底边在夹爪之下），与机器人动作丝滑同步（姿态平滑已由管理器驱动）。
- 触发"放气"后，该物体就地放下：位置做盆地吸附（优先吸入最近的空格/托盘，否则落到地面最近点），状态回到 `IDLE/PLACED`。

该机制在面板上暴露两个演示开关（吸气 / 放气），用户可手动控制，方便观察吸附与放下。

### 6.2 摄像头识别 → 颜色显现

摄像头识别既可用于动也可手动：

- **手动**：面板"识别全部 / 识别选中"，立即把 `revealed` 置 true，物体由黑变本色。
- **联动**：当 `HELD` 物体被末端运到"摄像头点位"附近时自动触发识别（贴合"到检测点拍照识别"的语义），同时生成一条记录（序号 / 颜色 / 置信度 / 照片占位）。

置信度用模拟值（可设定阈值，低于阈值判"未知"不投料），照片以占位框 + 时间轴编号呈现，为后续接真相机预留接口。

### 6.3 分拣节奏（数量自适应）

面板提供"演示分拣"：驱动**模拟机器人**（只改 simQ，不下发）在取料点 → 检测点 → 目标盒对应格 之间执行 7 步流程，逐步高亮，直到"取料区无料"或达目标个数。数量多几个少几个都自然结束。

## 七、运行过程可视化

在侧栏（或视口下方）放一条**分拣执行步进器**，复用 color_sort 的 7 步：

```
移动到取料点 → 吸气 → 移到检测点 → 拍照识别 → 按颜色放位 → 放气 → 结束
```

- 当前步高亮脉动，已完成步打勾，未到步置灰。
- 在"拍照识别"一步展示本次照片占位 + 颜色标签 + 置信度（中文标签）。
- 与 6.3 的演示联动：模拟机器人动到哪一步，步进器就亮到哪一步。

## 九、实施阶段

1. **P1 场景合约**：源盒 + 9 物体 + 目标盒 + 摄像头点位，初始全黑，形状与布局成型。
2. **P2 交互与碰撞**：拾取 / 拖拽 / 调大小 / 增删 / 防穿透，接入 P1 的物体。
3. **P3 动态机制**：吸气跟随、放气放下、识别显色、数量自适应循环。
4. **P4 运行可视化**：分拣步进器与 6.3 演示联动，展示拍照占位 / 颜色 / 置信度。
5. **P5 守卫与构建**：补 `verify_simobjects`、跑 `pytest / verify / vite build` 全绿，浏览器实测。

## 十、风险与对策

- **拾取与 OrbitControls 冲突**：拖拽期间禁 orbit，松手恢复。
- **多视图共享单场景**：物体在所有 3D 视图可见，正好体现"模拟"属性；隐藏视图不 resize，沿用既有逻辑。
- **检测点定位需贴近真实机器**：初始常量可调，面板提供微调并记忆到 localStorage，后续标定真机点位即可替换。
- **装配自检不受影响**：manager 的自检只量官方数模零件，不涉及新增物体。

## 十一、验收准则

- 边界内任意拖放物体都不会与地板/其他物体/托盘穿透。
- 吸气后物体随末端移动，放气后落回托盘空位或地面。
- 9 个初始黑色的物体经识别后各自显现红/绿/蓝，且与隐藏真色一致。
- 演示分拣按 7 步高亮推进、数量可多可少地在源盒→目标盒间搬运。
- `vite build` 与既有守卫全绿。
