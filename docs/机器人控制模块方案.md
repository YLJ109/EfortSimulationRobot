# 机器人控制 / 指令下发模块 — 方案（含安全边界）

> 需求：通过电脑直接操控机器人，或下发指令。
> 结论：**能做，但必须分级放开；真机控制当前缺关键前提（控制协议文档）。**

---

## 一、可行性结论

| 项 | 状态 |
|---|---|
| 现有能力 | Modbus **只读**姿态（reg10–21 = J1–J6，实测反推） |
| 参考项目 | `EFORT_Camera_Python_OpenCv` **只有只读代码**（`robot_modbus.py` 仅 FC1/2/3/4 读） |
| 控制寄存器映射 | **未知** —— Robox 控制器的控制地址/写入格式没有资料 |
| 结论 | L1（预演）可立即做；**L3（真机控制）需先拿到控制接口文档** |

---

## 二、安全声明（必读）

工业机器人 **8 kg 负载 / 712 mm 臂展**，误动作可致**人身伤害或设备损坏**。任何真机控制必须满足：

1. 现场清场、人员撤离、**物理急停在手**；
2. 单人操作、二次确认；
3. 系统内置：**软限位 / 速度限制 / 一键急停 / 操作日志**；
4. 先仿真验证，再逐级放开，**禁止一步到位**。

> 本方案默认：**控制系统默认关闭**，需显式启用并二次确认。

---

## 三、三级能力（按风险分层，逐级放开）

| 级别 | 能力 | 风险 | 依赖 | 可否现在做 |
|---|---|---|---|---|
| **L1 指令预演** | 输入目标（关节角 or TCP）→ IK + 限位 + 可达校验 → **3D 仿真走一遍**，**不发真机** | 零 | 现有 FK + **新增 IK** | ✅ 可立即做 |
| **L2 通信握手** | 读控制器状态/模式/使能位，验证控制链路 | 极低 | 控制协议文档 | ⏳ 待文档 |
| **L3 真机控制** | 单轴点动 / 移动到目标位 / 程序下发 | **高** | 协议文档 + 远程模式 + 安全环境 | ⏳ 待文档+环境 |

---

## 四、建议路径

**第一步（现在就能做）：L1 指令预演模块**
- 零风险、立即可用，且是 L3 的**必要基础**（限位/可达/轨迹校验算法通用）；
- 让你先在虚拟环境里"试算指令"，确认无误，将来再对接真机。

**第二步：拿到控制协议后，做 L2 握手验证**（只读状态，不发运动指令）。

**第三步：安全环境 + 看护下，做 L3 单轴微动**，逐步放开。

---

## 五、L1 功能设计（本次可实现）

**输入方式（两种模式）**
- **关节模式**：直接输入 J1–J6 目标角
- **直角/机器人模式**：输入 TCP 的 X/Y/Z（+姿态），由 **IK** 反解关节角

**校验（执行前）**
- 软限位：每轴 min/max（官方行程）
- 可达性：目标点是否在 712mm 工作空间内
- 速度/耗时估算

**预演（仿真执行）**
- 3D 模型按插值轨迹走一遍（可选倍速）
- 轨迹可视化（末端走过的路径）

**指令单**
- 生成结构化指令（JSON：目标、模式、速度），供将来下行到真机

**记录**
- 预演记录入库（可回溯）

---

## 六、L3（真机控制）需要你提供

1. **Robox 控制接口文档**：Modbus 控制寄存器地址表，或 TCP/IP 指令格式；
2. 控制器如何进入**远程控制模式**、伺服使能方式；
3. 确认测试环境安全（清场 + 急停 + 责任人）。

> 在拿到 (1) 之前，**不做任何真机写入**——盲写寄存器是危险且不可控的。

---

## 七、所需技术实现（L1）

| 模块 | 说明 |
|---|---|
| 逆运动学 IK | 新增 `kinematics.ikine()`（数值法：阻尼最小二乘 / 雅可比伪逆） |
| 轨迹插值 | 关节空间线性插值（后续可加 S 曲线） |
| 校验器 | 限位 / 可达 / 工作空间 |
| 后端接口 | `POST /api/control/preview`（只算不发）、`GET /api/control/limits` |
| 前端 | 模拟视图加「指令」面板：模式切换 + 目标输入 + 预演 + 指令单 |
