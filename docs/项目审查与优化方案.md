# EfortSimulationRobot — 代码审查与优化方案

> 审查范围：后端 (FastAPI / Modbus / 采集器 / DB)、前端 (Three.js 单页)、视觉检测服务。
> 目标：**保证正常运行、消除缺陷、去除功能重复**。按优先级分级。

---

## 一、缺陷清单

### P0 — 必须修复（影响正确性）

**P0-1 采集器"模拟模式不可恢复"（真 bug）**
`backend/app/services/collector.py`：真实 Modbus 读取**失败一次**即置 `self.simulated = True`；
下一轮循环 `if self.simulated:` 命中，**从此永久走模拟分支，不再重试真实读取**，必须重启后端才能恢复。
> 影响：现场网络抖动一次，监控画面就永久变成模拟数据，且界面上"数据来源"显示失真。
> 修复：失败仅作**当轮兜底**，不改变模式；连续失败 N 次才临时降级，并周期重试恢复。

**P0-2 `sampling.read_hz` 配置不生效**
循环频率取 `max(read_hz=10, push_hz=20)=20Hz`，但每轮都调用 `modbus.read_pose()`，
实际以 **20Hz** 读控制器（配置是 10Hz）。
> 影响：配置形同虚设，控制器通信负载翻倍。
> 修复：按 `read_hz` 节流读取，关节值缓存复用。

### P1 — 建议修复（性能 / 健壮性）

**P1-1 Modbus 每轮新建 TCP 连接**
`modbus.read_pose()` 每次调用都 `socket()→connect()→close()`，20Hz 下每秒新建 20 个连接。
> 修复：**复用长连接**，异常时重建。

**P1-2 WebSocket 广播无背压**
`hub.broadcast()` 每帧对每个客户端 `asyncio.ensure_future(...)`；客户端网络慢时 task 持续堆积 → 延迟、内存上涨。
> 修复：**每客户端只保留最新帧**（丢弃积压），或加有界队列。

**P1-3 SQLite 未启用 WAL**
采集线程写入 + API 并发读取，未开 WAL 时可能偶发 `database is locked`。
> 修复：连接时 `PRAGMA journal_mode=WAL` + `busy_timeout`。

### P2 — 代码质量 / 死代码

**P2-1 `HealthOut` 重复定义**
`backend/app/schemas/pose.py` 与 `api/robot.py` 内联各有一份；`schemas/pose.py` 的
`PoseOut/WsMessage/HealthOut` **实际均未被使用**。
> 修复：统一到 `schemas/`，`robot.py` 引用之（消除重复 + 死代码）。

**P2-2 `events` 表 / `insert_event` 从未写入**（死代码，但有价值 → 见新功能 B）

**P2-3 `sessions` 表 + `start_session/end_session/prune_old_poses` 未被调用**
且配置 `history_retention_days` **未生效**（历史不会自动清理，库会无限增长）。
> 修复：启动时按保留天数清理一次 + 定时清理。

**P2-4 `@app.on_event` 已弃用**
FastAPI 新版推荐 `lifespan` 上下文管理器。
> 修复：迁移到 lifespan。

**P2-5 前端未用端点**
`/api/pose`、`/api/history`（历史回放已移除）、`/api/export/csv` 前端均无调用。
> 处置：`/api/*` 作为开放 API 保留（供外部集成），但补充前端入口（见新功能 C），或按需精简。

## 二、功能重复核查（用户重点关注）

| 位置 | 判断 | 结论 |
|---|---|---|
| 真实监控 / 模拟仿真 各有「关节角」「末端 TCP」 | 数据源不同（真机 vs 模拟） | **非重复**，合理 |
| 真实监控 / 模拟仿真 各有「录制控制」 | 共用同一录制引擎，就近录制 | **非重复**，刻意设计 |
| 录制库 | 已集中到「录制回放」Tab | **无重复** |
| `HealthOut` 两份定义 + `schemas/pose.py` 死代码 | 同名不同处 | **真重复** → P2-1 修 |
| 历史回放 vs 录制回放 | 前者已删除 | **已消除** |

> 结论：UI 层无实质重复；**唯一真重复在代码层（P2-1）**，本次修掉。

## 三、建议新增功能（按价值排序）

**A. 运动模式：关节模式 / 笛卡尔模式**（你提的）
模拟视图增加模式切换：
- **关节模式**：逐轴调角（现有）
- **笛卡尔模式**：直接给 TCP 的 X/Y/Z（+姿态），后端 **逆运动学 (IK)** 解算关节角
> 现状：`kinematics.py` **只有正运动学 (FK)，没有 IK**，需新增（数值法：阻尼最小二乘 / 雅可比伪逆，交互够用）。
> 价值：高——贴近真实示教器交互；也让模拟具备"给目标点、自动求解"能力。

**B. 限位告警接入 `events` 表**
关节接近/超限、连接断开/恢复 → 写事件 + 前端提示。让现成却闲置的 `events` 表活起来。
> 价值：高——现场安全相关，且复用已有表。

**C. 数据导出入口**：前端加「导出 CSV」按钮（后端 `/api/export/csv` 已就绪）。
> 价值：中——补齐"能存不能取"的缺口。

**D. 录制增强**：倍速播放 (0.5×/1×/2×)、导出 CSV（与 JSON 并行）。
> 价值：中。

**E. 视觉检测记录入库**：检测快照 + 目标列表存库，可回溯查询。
> 价值：中。
