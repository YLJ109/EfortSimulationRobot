# 方案书｜点位执行 / 示教 / 点动 / 残影预演 全面升级（阶段 5）

> 机型：EFORT ER8-700H（6 轴） · 控制器 Modbus TCP 192.168.1.12:502
> 架构：FastAPI + Vue3(Vite) + Pinia + Three.js（单场景单模型）
> 版本基线：后端 v0.3.0 / 前端阶段 0~4 已完成（鉴权门、执行引擎、运维审计、加固）

## 0. 一句话目标

把「点位执行」页从"填数字 + 点按钮"升级为 **示教器级操作台**：
**滑块示教 → 点动微调 → 残影预演 → 单文件执行/空跑测试 → 摄像头复核** 的闭环，
并在每一步都保留既有安全门（控制令牌、急停、围栏互锁、审计留痕）。

```
┌───────────────────────────▼── 后端 FastAPI ─────────────────────┐

│ services/safety_guard.py（围栏互锁兜底）                         │
│ services/events.py（审计总线：落库+WS+日志，永不抛）             │
└─────────────────────────────────────────────────────────────────┘
```

**设计原则（沿用既有铁律）**

1. **安全左移 + 服务端兜底**：前端拦截只是体验，后端每个写接口再判一次（令牌 / 急停 / 围栏 / 限位）。
2. **只算不发的接口显式标注 `readonly: true`**（preview / ik / dry-run），杜绝"预演变下发"。
3. **不破坏单场景单模型**（`three/manager.js` 的既有不变量），新增对象必须显式登记、可开关、可销毁。
4. **不改旧表结构**（`create_all()` 不补列），新能力一律新建表或纯计算。
5. **图标全部 SVG**（Icon 组件），不引入 emoji。

## 3. R1 + R2｜滑块示教与双模式

### 3.1 交互设计

```
类型 (•) 关节角  ( ) 直角坐标
────────────────────────────────────────────
J1  ├──────●──────────────┤  -170.0   [-170, 170]
J2  ├───●─────────────────┤   -90.0   [-170,  90]
...（6 轴，量程取自 /api/meta 的 joint_limits，兜底 ±180）
[取当前姿态] [回零] [残影预演 ✓] [保存]
```

* 直角模式滑块：`X/Y/Z ∈ [-900, 900] / [-900, 900] / [0, 1400]` mm，`Rx/Ry/Rz ∈ [-180, 180]`°。
* 每条滑块右侧显示**实时数值 + 量程**，`font-variant-numeric: tabular-nums` 防抖。
* 拖动即预览：关节模式直接 `applyRobotPose(q)`；直角模式 **150ms 防抖** 调 `/control/ik`，成功再驱动模型（失败显示误差不驱动）。
* 「取当前姿态」：`robot.latestPose` → 灌回滑块（真机在线时＝真机姿态，离线＝仿真姿态）。
* 「回零」：J1~J6 = 0（直角模式回默认安全 TCP）。
* 直角模式保存时仍走既有链路：`/control/ik` → joints → `/points`，`tcp` 一并落库。

### 3.2 与残影的联动

拖动滑块时，`ghost` 显示"当前滑块目标"，主机保持"当前实际姿态"，
两者叠加形成 **A/B 对比**（Δ per joint + 末端直线距离 mm + 预计耗时 s）。

## 4. R6｜点动引擎 Jog（示教器规范对齐）

### 4.1 参考的工业规范（已调研）

| 规范点 | 来源 | 本方案落地 |
|---|---|---|
| T1 教学模式限速 250 mm/s（关节角速度上限） | ISO 10218-1 / FANUC T1 | `motion.jog.max_speed_dps = 30`（可配），前端滑块硬夹 |
| 三段使能开关（Deadman）：松手或握死都停 | FANUC/安川示教器 | **看门狗**：`watchdog_ms=1500`，前端按住时每 400ms 发 keepalive |
| 增量点动（×1/×10/×100 或 0.1/1/5/10°） | Mecademic / FANUC | `step_deg` 选择 0.1 / 1 / 5 / 10°，单击走固定角度 |
| 连续点动（按住 SHIFT + 方向键） | FANUC / MecaPortal | `mode=start` 按住不放，松开 `mode=stop` |
| 点动前必须无报警、互锁闭合 | 通用 | 急停 / 围栏 danger|hit / 限位到达 → 立即停止并审计 |

### 4.2 后端：`backend/app/services/jog.py`（★新增单例）

```
JogEngine
├─ step(joint, dir, angle_deg, speed_dps)   # 增量点动，一次一发
├─ start(joint, dir, speed_dps)             # 连续点动：起线程
├─ keepalive()                              # 死人开关保持信号（刷新 watchdog）
├─ stop(reason)                             # user/watchdog/estop/fence/limit/error
├─ _loop()                                  # tick=100ms：增量→限位裁剪→motion.command
└─ state() → {active, joint, dir, speed_dps, elapsed_ms, watchdog_left_ms, target, reason}
```

* 线程内**每 tick 都过三道关**：`motion.state().stopped`（急停）→ `safety_guard.check()`（围栏）→ 关节限位（到限位即停并记原因）。
* 换轴/换向必须先停（避免两个方向同时写同一关节）。
* 连续点动的基准姿态在 `start()` 时快照（`motion.last_target` → 采集器实时姿态兜底），逐 tick 累加，避免"读回滞后"造成抖动。
* 全部下发仍经 `motion.command()` → 真实下发继续受 `EFORT_REAL_MOTION + motion.real_write` 双确认。

### 4.3 API 契约

```http
POST /api/control/jog          # 需控制令牌
{ "mode": "step"|"start"|"stop"|"keepalive",
  "joint": 1..6, "dir": 1|-1,
  "speed_dps": 0.1..30, "angle_deg": 0.1..90 }
→ { ok, action, active, joint, dir, speed_dps, elapsed_ms,
    watchdog_left_ms, target, reason, mode:"sim"|"real" }
GET  /api/control/jog          # 查询点动状态
```

* 事件审计：`control.jog_step` / `control.jog_start` / `control.jog_stop` / `control.jog_blocked`。
* `/control/estop` 触发时同步 `jog.stop("estop")`（急停必须能掐断点动）。

### 4.4 前端交互

```
模式 (•) 增量点动 步长[0.1|1|5|10]°   ( ) 按住连续点动
速度 ├───────●──────┤ 15 °/s（上限 30，T1 教学限速）
耗时 ≈ 0.33 s（步长 ÷ 速度，实时显示）

        [ − ]   [ + ]
  J1       ▣      ▣
  J2       ▣      ▣
  ... J6
状态：J3 + 向 · 15°/s · 已运行 0.8s · 看门狗剩余 0.7s
提示：松开即停；1.5s 无保持信号自动停（等效示教器三段使能开关）
```

* `pointerdown` 起、`pointerup / pointercancel / pointerleave / window blur / visibilitychange` 停（五重保险，防止"按住切窗口机器人还在跑"）。
* 连续模式期间每 400ms 发 keepalive，返回体即最新 state（顺带把 target 喂给 3D 预览）。
* 禁止态：`!auth.controlActive` / `UNSAFE(lastState ∈ danger,hit)` / `estopState.stopped` → 按钮 disabled + 原因提示。

## 5. R3 + R4｜单文件执行与试运行（空跑测试）

### 5.1 解析顺序（后端 `_resolve_file`）

1. **数据库执行程序**按名（先精确后包含，忽略大小写与 `.json` 后缀）
2. **数据库预设点位**按名（同上）
3. **磁盘文件** `<项目根>/programs/*.json`（可用 `EFORT_PROGRAM_DIR` 覆盖）

磁盘文件格式兼容三种：

* `{"format":"efort-program/v1","name":"…","items":[…]}`（程序导出格式）
* `{"name":"…","steps":[…]}`（简写）
* `{"name":"…","joints":[6]}` 或 `{"tcp":{…}}`（单点点位）

步骤条目支持 `point_id`（回数据库查关节角）或内联 `joints` / `tcp`。

### 5.2 路径安全

```
_safe_file(name):
  basename() 丢弃一切目录片段 → 拒绝 "."/".."/含 ".."
  补 .json → abspath → commonpath 必须仍在 programs 目录内（跨盘 ValueError 也拒绝）
```
★ 杜绝 `../../config/robot.yaml` 这类穿越读取。

### 5.3 API 契约

```http
GET  /api/control/files                      # 候选清单：DB 程序/点位 + 磁盘 json
POST /api/control/run-file                   # 需控制令牌
{ "filename":"demo_pick.json", "dry_run":true, "speed_pct":100, "steps":40 }
```

* `dry_run=true`（**默认 true**）：逐步 `_compute_preview()` → 汇总 `violations/warnings/solver/distance_mm`，**绝不调用 `motion.command`**。
* `dry_run=false`：逐步过 `safety_guard.check()` → 直角步骤先 IK → `motion.command()` → 步间 `dwell + 200ms`。
* 返回：`{ok, dry_run, kind, name, source, path, count, passed, duration_ms, readonly, steps[]}`。
* 未命中 → **404 + `detail.candidates`**（前端直接把候选名列出来，用户点一下即可填入）。
* 审计：`control.dry_run` / `control.run_file` / `control.run_file_missing` / `control.move_blocked`。

### 5.4 前端卡片

```
单文件执行
文件名 [ demo_pick.json ▾ ]  ← datalist 来自 /control/files
[▶ 执行]  [🧪 试运行测试]     （图标：play / flask，SVG）
──────────────────────────────
来源：file · 程序 · 3 步 · 通过 3/3 · 只读预演 ✓
1 ✓ 取件位   Δ TCP 412mm   IK ok(0.02mm)
2 ✓ 过渡位   Δ TCP 268mm   IK ok(0.00mm)
3 ⚠ 放件位   J3 超出限位 [−85,150] → 已阻止
```

* 试运行结果不写库、不动 3D（只高亮问题步）；真实执行时逐步 `animateTo()` 预览。
* 附带一个开箱即用的示例文件 `programs/demo_pick_place.json`（内联 joints，不依赖数据库 id）。

## 7. R7｜残影（Ghost）预演 ★重点

### 7.1 需求本质

"到达点位后，用第二个半透明模型预测/显示下一个点位在哪儿" ——
本质是 **A/B 双姿态同屏对照**：实体机＝当前姿态，残影机＝目标姿态。

### 7.2 方案选型（含被否决项）

| 方案 | 结论 | 理由 |
|---|---|---|
| A. `official.root.clone()` | ❌ 否决 | 项目既有铁律：官方 GLB **clone 单 mesh 会放大 1000 倍**（scale(0.001) 在被克隆节点上重复/丢失），且装配自检会失败 |
| B. 二次 `GLTFLoader.loadAsync` 再建一台官方残影 | ⭕ 可选（默认关） | 与 clone 无关、安全，但 +4.2MB 显存/解析开销 |
| **C. 程序化模型再建一份，改半透明材质** | ✅ **默认** | `buildRobot()` 是纯函数、可重复调用；零 clone 风险、几何轻、材质完全可控；与官方数模"外观不同但位姿同源"（同一 DH、同一零位） |

> 说明：残影的使命是"**看位姿**"不是"看外观"，用同一 DH 驱动的程序化连杆即可精确表达目标姿态；
> 需要"官方外观残影"时，打开开关走方案 B（独立加载，缓存 gltf 供二次构建）。

### 7.3 模块设计：`frontend/src/three/ghost.js`（★新增）

```js
export function ensureGhost(dh, mounting)   // 懒创建，幂等；与 manager 共享 scene
export function applyGhostPose(qDeg)        // 立即到位（残影不做平滑，避免拖影误判）
export function setGhostVisible(v)          // 开关
export function setGhostState(state)        // safe|warn|danger|hit → 颜色
export function setGhostTarget(tcpMm)       // 目标点标记 + 连线
export function disposeGhost()              // 卸载销毁（视图退出/切换）
```

材质规范（**取色铁律：一律走 `colorOf()`，绝不写 `colors[state] || 默认绿`**）：

```js
new THREE.MeshStandardMaterial({
  color: GHOST_COLOR[state], transparent: true, opacity: 0.26,
  depthWrite: false,           // 关键：残影不写深度，实体机永远压在前面
  roughness: .5, metalness: .0, side: THREE.DoubleSide,
})
```

* `castShadow = receiveShadow = false`，`raycast = () => {}`（残影不可拾取）。
* 渲染顺序：`renderOrder = 2`，实体机保持默认。
* **不参与**实体机的实时读数（`getActiveRoot()/getGroundRoot()` 仍只返回实体机），避免"残影触发实时报警"的假阳性；
  但**参与下发判据** —— 见 7.6。
* 抬升量复用 `PLATFORM_H`（与实体机同一立足面），并写 headless 断言钉死：残影底面 y ≈ 实体机底面 y。

### 7.4 视觉辅助（让"预测"一眼可读）

1. **TCP 连线**：当前 TCP → 目标 TCP 的虚线（`LineDashedMaterial`），长度＝末端位移。
2. **目标标记**：目标点地面投影圈 + 十字准星（贴合地坪/台面 `PLATFORM_H+0.002`）。
3. **数据条**：ΔJ1~ΔJ6、末端直线距离 mm、旋转量、按当前速度预计耗时 s。
4. **状态配色**：可达且无越限＝青绿；接近限位/大位移＝琥珀；IK 失败或超限位＝红（并标 ✕）。

### 7.5 触发时机

| 场景 | 残影显示 |
|---|---|
| 编辑点位、拖动滑块 | 实时跟随滑块（防抖 60ms） |
| 选中列表中的某个点位（hover/点击"预演"） | 显示该点位目标姿态 |
| 程序运行时 | 显示**下一步**点位（"下一站"预告） |
| 点动时 | 不显示（避免干扰），点动结束显示本次落点 |
| 离开执行页 | 自动隐藏并 `disposeGhost()` |

### 7.6 下发判据：按**残影目标位姿**判定（现场口径）

现场要求：**点位 / 示教 / 程序不按实体机"现在在哪"拦截** —— 它现在在哪与"要去哪"无关；
只要残影预演的目标位姿不碰撞、不泛红，就允许运动。

**唯一评估入口**：`three/manager.js` 的 `evalSafety(tSec)`

| 残影是否可见 | 量的是谁 | 返回 `source` |
|---|---|---|
| 可见（正在预演下一个点位） | 残影的**目标位姿**（`ghost.withTarget`，量完立刻还原动画姿态，视觉零跳变） | `"ghost"` |
| 不可见 | 实体机的**当前位姿** | `"robot"` |

三处消费方**同源**读这一份结果，不允许各算各的：

1. **围栏面板 / 地面垫变色** —— 预演时就按目标位姿变色（"那片红"就是拒绝的理由）；
2. **上报后端** `/api/safety/live` —— `safety_guard.check()` 据此在 move / run-file / jog 兜底；
3. **前端下发门控** `stores/exec.js` 的 `gateAt(qDeg)` —— 同步执行，不依赖渲染循环那一帧，
   所以"没悬停过就直接点执行"也拦得住。

拦截规则（`STATE_RANK`）：`safe` / `warn` 放行，`danger` / `hit` 拦截。
接近（warn）不等于撞上，仍允许运动 —— 这也是"不拦截"的边界所在。

**点动是唯一例外**：点动是"就地增量走"，没有目标位姿可预演，只能看实体机当前位姿
（`UNSAFE` / `canJog`）。判据与点位/示教/程序**刻意分开**，互不借用。

## 8. 安全设计（贯穿全部新能力）

| 风险 | 防线 |
|---|---|
| 有人绕过界面直接调 API | 所有写接口 `require_control`（401）；admin 专属仍 `require_admin`（403） |
| 围栏危险时下发 | `safety_guard.check()` 在 move / run-file / jog 每步都判，danger/hit → 409 + 审计 |

## 附：关键既有约束（改动时不得违反）

1. `apiUrl()/apiControl()` 自带 `/api` 前缀 → 调用只传 `"/points"` 这类**去前缀**路径。
2. 官方数模必须用 GLB **原件**，禁止 clone；`root.position.y` 必须在所有 `attach()` 之后设置。
3. 围栏取色一律 `colorOf(state)/opacityOf(state)`，不得写 `colors[state] || "#2ecc71"`。
4. 给已存在的表加列必须**新建表**（`create_all()` 不补列）。
5. 测试口令在 `conftest.py` **模块级**强制赋值（本机 `.env` 会覆盖 fixture）。
6. 后台进程在沙箱会被回收 → 长跑验证用 TestClient 写 pytest。
7. 构建用托管 node 直跑 `node_modules/vite/bin/vite.js`（npm 全局会 OOM）。
