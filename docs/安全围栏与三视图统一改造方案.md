## 一、现状与病根（先把问题钉死）

### 1.1 已确认的 Bug：官方模型被建了多份 → 第二份错位

这是「模拟仿真机型渲染异常」的真正原因，**不是模型尺寸错，也不是取景问题**。

证据链：

| 事实 | 数值 |
|---|---|
| 官方数模原始尺寸（STEP 1:1） | 高 **810 mm**、跨度 688 mm、底座 Ø440 mm |
| 官方手册 ER8-700H 可达半径 | **712 mm**、本体 41 kg |
| 渲染正确时世界包围盒 | `0.688 × 0.810 × 0.256 m` ✅（已用真实 GLB 顶点端到端验过） |
| 渲染异常时世界包围盒 | `687.705 × 256.000 × 810.300` —— **原始 mm 被当成 m** ❌ |

根因在代码：

```js
// ❌ 旧代码：第二份模型用 mesh.clone()，父级丢了
officialRobots.live = buildArticulatedOfficial("live", parts, ...);              // 原件（有父级，正确）
officialRobots.sim  = buildArticulatedOfficial("sim",  parts.map(p => p.clone()), ...); // clone（无父级，炸）
```

`Object3D.attach()` 的补偿公式是：

```
newLocal = inv(目标节点.matrixWorld) · 源父级.matrixWorld · oldLocal
```

GLB 里零件挂在带 `rotX(-90°) + scale(0.001)` 的根节点下，这个"源父级"正是把 **mm → m** 的关键。
`mesh.clone()` 出来的对象 `parent === null`，源父级矩阵退化成单位阵 → mm 顶点被直接当米用 → 模型放大 1000 倍并错位。

已用 Node 复现确认（两条路径对照）：

```
A 单独 clone 零件 → 顶点世界坐标 (300, 0, 500) m   ← 错
B clone 整棵子树 → 顶点世界坐标 (0.30, 0.50, 0) m  ← 对
```

> 当前已做的临时修复：`src.clone(true)` 克隆整棵子树（保留父级）。但这只是**止血**，没解决"为什么要建两份"。

### 1.2 结构性隐患：三视图 = 三套场景 + 多套模型

```js
const scenes = {};          // live / sim / rec 各一套 scene + camera + controls
const robots = {};          // 三份程序化模型
const officialRobots = {};  // 两份官方模型
```

问题：
- 模型份数随视图数增长，任何一处 clone/attach 写法不一致就会重演 1.1 的 bug
- 三套模板各写各的，UI 与模型状态容易不一致
- 显存/内存浪费（每份官方模型 24 个零件）

### 1.3 安全围栏参数全部硬编码

`CELL_HALF / WARN_RATIO / DANGER_RATIO / 颜色 / 闪烁频率` 都写死在 `manager.js`，改一个数字要重新构建，无法现场调试。

### 1.4 配置无持久化

刷新页面回到默认值，调好的参数全丢。

## 三、架构改造

### 3.1 方案 A：单一场景 + 单一模型（**推荐**）

```
                 ┌─────────────────────────────┐
                 │   唯一 WebGLRenderer         │
                 │   唯一 Scene / Camera        │
                 │   程序化模型 ×1              │
                 │   官方模型   ×1 (GLB 原件)   │
                 │   工作间 + 围栏 ×1           │
                 └──────────────┬──────────────┘
                                │ canvas 在三个容器间搬移
              ┌─────────────────┼─────────────────┐
         真实监控容器        模拟仿真容器       录制回放容器
```

数据模型：

```js
// three/manager.js（改造后）
let scene, camera, controls;              // 只有一套
let robot, officialRobot;                 // 各一份
const containers = { live: null, sim: null, rec: null };
let activeView = "live";
```

- 三个视图组件不再 `registerScene('live'|'sim'|'rec')`，改为 `registerView(view, el)` 只登记容器
- 切视图 = `containers[view].appendChild(canvas)` + `resize()`，**场景和模型不动**
- 官方模型用 GLB **原件**直接建，不 clone → `attach()` 天然正确
- 外观切换 = 两个 root 的 `visible` 互切（都在同一个 scene 里）

**优点**：根治多份模型；内存/显存降为 1/3；三视图视觉绝对一致；改动集中在 manager + 三个组件去掉注册逻辑。
**代价**：三个视图共用一个相机（切视图不保留各自视角）。若需要每视图独立视角，见方案 B。

### 3.2 方案 B：三场景共享一个模型实例（备选）

保留三套 scene/camera（各自记住视角），但模型**只有一个实例**，切视图时：

```js
scenes[view].scene.add(modelRoot);   // three 的 add 会自动从旧父级移除
```

**优点**：每视图独立视角；改动比 A 小（不动组件注册逻辑）。
**代价**：仍是三套场景；模型在场景间搬移（每帧切换时有 `add/remove`，开销可忽略但仍存在）。

> **建议**：选 **A**。你要的是"三个视图一个模板"，A 最贴合；视角记忆不重要（OrbitControls 全局一套反而更符合"一个模板")。
> 如果你希望"真实监控转到的角度，切到仿真还保持"，告诉我，改 B。

```json
{
  "enabled": true,
  "shape": "rect",
  "center": { "x": 0.0, "z": 0.0 },
  "half":   { "x": 0.82, "z": 0.82 },
  "corners": [ [-0.82,-0.82], [0.82,-0.82], [0.82,0.82], [-0.82,0.82] ],
  "height": 1.2,
  "thickness": 0.02,
  "posts": { "enabled": true, "size": 0.1, "color": "#f2c500" },
  "thresholds": {
    "basis": "halfwidth",
    "warn": 0.30,
    "danger": 0.10,
    "fixed_mm": 300
  },
  "colors": {
    "safe": "#2ecc71", "warn": "#f2c500",
    "danger": "#e5484d", "hit": "#ff2020"
  },
  "opacity": { "safe": 0.11, "warn": 0.20, "danger": 0.30, "hit": 0.45 },

```

字段说明：

| 字段 | 作用 | 对应你的诉求 |
|---|---|---|
| `shape` | `rect` 轴对齐矩形 / `quad` 任意四点四边形 | 「长方形 / 四个点」 |
| `center` + `half` | 矩形模式：中心 + 半宽/半深 | 调大小、远近 |
| `corners` | 四点模式：四个角 (x,z) 独立可调 | 「四个点那种」 |
| `height` / `thickness` | 围栏高与厚 | 其他设置 |
| `posts` | 四角黄柱开关/截面/颜色 | 角柱 |
| `thresholds.basis` | `halfwidth`=余量占中心到边距离 / `fixed`=固定毫米 | 分级基准 |
| `thresholds.warn/danger` | 接近 30% / 危险 10% —— **滑块可调** | 「调接近/远离」 |
| `colors` / `opacity` | 四态颜色与透明度 | 「黄色、红色」 |
| `blink` | 闪烁频率与透明度区间 | 「闪烁」 |
| `alarm` | 顶部报警条/底部状态片开关，报警条最低触发级别 | 报警 |

### 4.2 后端接口（新增 `backend/app/api/safety.py`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/safety` | 读取配置（文件不存在则写默认值再返回） |
| PUT | `/api/safety` | 校验 + 落盘 `config/safety.json` |
| POST | `/api/safety/reset` | 恢复出厂默认 |

存储选型：**JSON 文件**（与 `config/robot.yaml` 同目录），不动数据库 schema，改动最小、易备份、便于你手工改。

校验要点（后端做，防止前端传坏值）：
- `half.x/z` ∈ [0.2, 3.0]，`height` ∈ [0.3, 3.0]
- `warn` > `danger`，且都在 (0,1)
- `corners` 长度为 4，且构成简单四边形（不自交）
- 颜色必须是 `#RRGGBB`

**SafetyPanel.vue 控件清单**

- 围栏总开关
- 形状切换：`矩形` / `四点`
- 矩形模式：中心 X/Z 滑块、半宽 X、半深 Z、高度、厚度
- 四点模式：四个角的 X/Z 八个数字输入（或四个小 2D 拖拽点）

- 基准：下拉（围栏半宽 / 固定毫米）+ 固定毫米输入框

- 闪烁：频率 Hz、透明度区间
- 报警：报警条开关、状态片开关、报警条最低级别

交互约定：

- 点「保存」才写后端；未保存时按钮显示红点提示
- 点「重置」恢复默认并立即应用（可再点保存固化）

### 4.4 碰撞/接近度算法

**输入**：机器人当前世界 AABB（`Box3.setFromObject(modelRoot)`，已验证开销可忽略）

**矩形模式**

```
clearance = min(
  (cx + hx) - box.max.x,   box.min.x - (cx - hx),   // ±X 两侧
  (cz + hz) - box.max.z,   box.min.z - (cz - hz)    // ±Z 两侧
)
basis = (basis === 'halfwidth') ? min(hx, hz) : fixed_mm/1000
ratio = clearance / basis
```

**四点模式**（任意四边形）

```
对四边形的每条边 e：
  取边的内法线 n（指向四边形内部）
  d_e = min over AABB 4 个水平角点 p  of  dot(n, p - e.a)
clearance = min over e of d_e       // 负值 = 已越界
```

**分级**

```
ratio <= 0            → hit    （红 + 闪烁 + 报警条）
ratio <  danger       → danger （红）
ratio <  warn         → warn   （黄）
else                  → safe   （绿）
```

**闪烁**

```
k = 0.5 + 0.5 * sin(2π · hz · t)          // hz 可配，默认 4Hz
opacity = lerp(blink.min, blink.max, k)
emissiveIntensity = 0.5 + 1.3 * k
```

### 4.5 状态广播

`onSafety(cb)` 仅在**状态变化**时回调（避免每帧刷 UI），载荷 `{ state, ratio, clearance }`。
→ 顶部报警条（danger/hit）、底部常驻状态片（四态）消费。
