# 方案书｜OpenCV 视觉颜色分拣（传送带长方形物体 → 颜色分类 → 拍照记录 → 播报）

> 场景：机器/传送带把**长方形物体**送到工业相机（海康 MV-CU120-10GM）前，**停留约 1 秒**，
> 相机检测 → 框出物体 → 判定颜色 → 拍照存档 → 记录 → 播报颜色。
> 要求：覆盖**常见全部颜色**。
> 版本：v2（在阶段 5 方案基础上的补充与优化） · 2026-09-23

---

## 0. 结论先行：能做，而且成熟 —— 但成败在"光"不在"算法"

| 问题 | 结论 |
|---|---|
| 能做吗？ | **能。** 颜色分类是工业视觉最成熟的场景之一（比缺陷检测、尺寸测量简单一个量级）。本项目相机、OpenCV、计算资源**全部现成**（相机 venv 里已有 `cv2 5.0 + numpy 2.5 + torch/ultralytics`）。 |
| 用 OpenCV 够吗？ | **够，且推荐为主力。** 背景差分 + 轮廓 + Lab/CIEDE2000 是标准解法，单帧 <15ms，1 秒停留绰绰有余（延迟预算 300ms）。YOLO 只在"背景复杂/要语义分割"时作为**可选增强**，不是必须。 |
| "所有常见颜色"能保证吗？ | 能覆盖 **16 类常见色**（见 §4.10 色卡表），但**必须现场标定**：不标定的"通用色表"在现场光照/材质下误判率会到 10~30%；标定后可稳定 ≥98%。 |
| 最大风险 | **不是算法，是光照与反光。** 白平衡漂移、LED 频闪、塑料高光、黑/白/银的边界、背景同色。方案 §5 逐条给了工程对策。 |
| 与机器人联动？ | 可以做闭环：颜色 → 触发不同点位/程序 → 机器人分拣入框（复用阶段 5 的 `/control/run-file` 与点位执行）。 |

**推荐交付节奏**：先做 **MVP（1 天能跑通）**，再上 **完整版（标定 + 记录 + 播报 + 联动）**。

* MVP：固定 ROI + 背景差分 + 主色提取 + ΔE 匹配 + 画面框选 + 控制台打印颜色。
* 完整版：+ 一键色卡标定 + 拍照存档 + 数据库记录 + 语音播报 + 分拣规则联动 + 前端视觉页 + 批量回归测试。

## 1. 需要先和你确认的现场参数（影响方案细节）

| # | 参数 | 为什么关键 | 默认值（先按此实现） |
|---|---|---|---|
| 1 | 物体尺寸/长宽比范围 | 决定面积阈值与矩形判定 | 30~300 mm，长宽比 1.2~6 |
| 2 | 物体材质 | 塑料/金属/纸/木 → 反光与色偏差异大 | 默认塑料哑光；金属需偏振 |
| 3 | 颜色清单（你们实际有几种？） | 直接决定色卡条目，越少越好判 | 先内置 16 类，现场可增删 |
| 4 | 背景是什么 | 背景板颜色决定分割难度 | 建议**中灰 18% 背景板**（对比度最优） |
| 5 | 光源 | 频闪/色温漂移是头号敌人 | 直流稳压白光 + 漫射罩；或曝光设为 10ms 整数倍 |
| 6 | "停留 1 秒"是怎么停的 | 有没有到位信号（传感器/PLC） | 无信号也能做（视觉稳定判定），有信号更稳（硬触发优先） |
| 7 | 一次视野里有几个物体 | 单物体 vs 多物体同时 | 先支持**多物体**（每个独立框+独立颜色） |
| 8 | 播报方式 | 前端语音 / 现场音柱 | 前端 Web Speech API（离线、中文、零成本）+ 可选后端 SAPI |

> 有到位信号（光电开关/PLC）就走**硬触发**；没有就走**视觉稳定判定**（本方案默认，通用性最强）。

## 2. 总体架构（复用现有，不另起炉灶）

```
[海康相机] → camera/camera_service.py (:8100)
                ├─ 抓帧线程(已有) → latest_frame(1280px 小图)
                ├─ YOLO 检测线程(已有，可选)
                └─ ★颜色检测线程 color_loop(新增，纯 OpenCV，<15ms/帧)
                     ├─ 背景建模/帧差 → 掩膜 → 轮廓 → 矩形筛选
                     ├─ 稳定判定状态机 → 触发一次
                     ├─ 主色提取(kmeans) → Lab → CIEDE2000 → 色卡匹配
                     ├─ 画框+中文标签 → 叠到 MJPEG 流(已有 _draw 管线)
                     └─ 拍照存档 camera/captures/{原图/裁剪/掩膜}
                          │ 新端点 /vision/*
                          ▼
              backend (:8000) api/vision.py(新增)
                ├─ 代理相机服务 + 记录落库(新表 vision_records)
                ├─ 事件总线 emit(category="vision") → WS 广播 + 审计
                └─ 分拣规则：颜色 → 点位/程序 → /control/run-file(需控制令牌)
                          │
                          ▼
              前端「视觉分拣」页(新增卡片/视图)
                ├─ 实时画面(带框+标签+置信度)
                ├─ 最近结果列表 + 缩略图 + 导出 CSV
                ├─ 色卡标定面板(一键采色)
                └─ 播报开关(Web Speech API)
```

**为什么把算法放在相机服务里？** 抓帧线程已有、小图已缓存、绘制管线已有 —— 放在这里**零额外抓帧开销、零跨进程传图**，延迟最低；后端只做"记录 + 联动"，职责干净。

## 3. 算法流水线（12 步，步步可验证）

### 3.1 触发方式（三选一，按现场条件自动降级）

| 方式 | 条件 | 实现 | 精度 |
|---|---|---|---|
| 硬触发（最优） | 有到位信号 | 相机软触发 / 后端监听 DI → 收到信号后延时 200ms 取帧 | 最高 |
| 视觉稳定判定（默认） | 无信号 | 见 §3.6 状态机 | 高 |
| 定时轮询 | 兜底 | 每 250ms 判一次 | 一般 |

### 3.2 ROI 与分辨率

* 抓帧后已是 **1280px 宽**（`STREAM_MAX_W`），再裁 ROI（传送带区域）后典型 **600×400** → 算法成本极低。
* ROI 可在前端**拖拽框选**（复用 CameraPanel 的拖拽交互），避免拍到传送带外的手/人/设备。

### 3.3 白平衡 / 色彩校正（**强烈建议做，性价比最高的一步**）

* **一键灰卡标定**：ROI 内放 18% 灰卡 → 采中位 RGB → 计算通道增益使灰卡 → 中灰 → 存 `calib.json`（r_gain/g_gain/b_gain）。
* **进阶（可选）**：24 色 ColorChecker → 最小二乘拟合 3×3 校正矩阵（含常数项），精度更高。
* **现场实物标定（最推荐）**：拿你们真实物料每色拍一张 → 自动写入该色的 **Lab 参考值**（见 §5）。比任何标准色卡都贴合实际。
* 有效性自检：标定后重拍灰卡，ΔE < 3 才提示"标定成功"。

### 3.4 目标分割（把物体从背景里抠出来）

**推荐主方案：背景差分 + 帧差双确认**（静态相机、固定背景 = 最稳最便宜）

```
MOG2: history=500, varThreshold=16, detectShadows=True
   ↓ 形态学 open(5×5) 去噪点 → close(5×5) 补孔洞 → dilate 3×3
   ↓ 阴影抑制（shadow 像素置 0）
双确认：|frame - background| > 12 的像素才保留（防 MOG2 把静止物体"学进背景"）
```

**备选/增强**：

* 背景会缓慢变化（光照漂移）→ MOG2 学习率 `learningRate=0.001`（低速更新）。
* 背景复杂或多物体粘连 → 上 **YOLOv8-seg**（已有 torch 环境）取实例掩膜；或 `cv2.ximgproc` 分水岭。
* 传送带在动（背景非静止）→ 改用 **帧差 + 运动停滞判定**：物体停住后帧差消失，用"上一张静止背景"做差分。

### 3.5 候选筛选与矩形判定（只认"长方形物体"）

```
轮廓 → minAreaRect → 过滤：
  area            ∈ [ROI 的 0.5%, 60%]
  min(w,h)        ≥ 40 px
  长宽比          ∈ [1.2, 8]
  矩形度 area/(w·h) ≥ 0.72        ← 长方形接近 1，异形件低
  实心度 area/hullArea ≥ 0.90
  轮廓近似        ≈ 4 顶点（cv2.approxPolyDP, ε=2%周长）
  质心在 ROI 内
  → NMS 去重(IoU > 0.5 合并)
```

### 3.6 稳定判定 + 只触发一次（1 秒停留的关键）

```
状态机：EMPTY → ENTER(发现目标) → STABLE(连续 N 帧稳定) → CAPTURED(已拍照记录) → LEAVE(目标消失/位移>阈值)
稳定判据：连续 3 帧（约 100ms）
   · 质心位移 < 3 px
   · 框面积变化 < 8%
   · 帧间 IoU  > 0.85
触发后进入 CAPTURED 并锁存，直到目标离开 ROI（或连续 10 帧无匹配）才回 EMPTY
→ 保证"停留 1 秒"只记录一次、只播报一次（不会连拍连报）
```

### 3.7 采样掩膜净化（决定颜色准不准的隐藏关键）

```
1) 掩膜腐蚀 4 px            → 去掉边缘混色/抗锯齿像素
2) 剔除高光：V > 0.96·255 或 L > 92   → 塑料反光点会毁掉主色
3) 剔除暗部：L < 10                   → 阴影/黑洞
4) 中心加权：权重 = exp(-d²/(2σ²))，σ = 0.35·物体短边  → 抗边缘漏背景
5) 有效像素 < 200 → 判"采样不足"，标记低置信，不播报
```

### 3.8 色彩空间与色差度量

* **主用 CIE Lab + CIEDE2000**（感知均匀、与设备无关、工业标准）。
* **不用 RGB**：设备相关、非线性，光照一变色值就飘。
* **HSV 只做调试可视化/快速兜底**：H 通道红色绕回 0/360、V 受光照影响大，不适合做最终判据。
* ΔE2000 自写 ~30 行 numpy（**零新依赖**，离线可装；比装 `colour-science` 更稳）。

### 3.9 主色提取

```
采样 N=5000 点(上限) → cv2.kmeans(k=3, 3 iter, eps=0.5)
取占比最大的簇 → 该簇中位 Lab（比均值抗离群点）
判据：
  主簇占比 ≥ 0.55 → 单色，正常判定
  0.35 ≤ 占比 < 0.55 → "多色/印花"，取最大簇但标 low_confidence
  占比 < 0.35 → 标"杂色"，建议人工复核
（可选）空间连通性检查：主色是否成片，避免噪点簇胜出
```

### 3.10 色卡匹配与命名（覆盖"所有常见颜色"）

内置 16 类（**初值仅供参考，务必现场标定覆盖**）：

| 中文 | 典型 sRGB | 近似 Lab (L,a,b) |
|---|---|---|
| 红 | #E02020 | 53, 80, 67 |
| 橙 | #FF7A18 | 68, 45, 60 |
| 黄 | #FFD400 | 86, −8, 88 |
| 草绿 | #4CAF50 | 62, −45, 45 |
| 深绿 | #1E6B34 | 38, −35, 22 |
| 青 | #00BFC8 | 72, −38, −12 |
| 天蓝 | #4FA8FF | 70, −6, −42 |
| 蓝 | #1F4FD8 | 38, 60, −95 |
| 深蓝 | #0E2A6B | 22, 30, −55 |
| 紫 | #8A3FC0 | 45, 55, −50 |
| 粉 | #FF9EC4 | 78, 32, 2 |
| 棕 | #7A4A22 | 40, 22, 34 |
| 米白 | #F0E4CC | 90, 2, 18 |
| 白 | #FFFFFF | 100, 0, 0 |
| 银灰 | #C8CDD2 | 82, −1, −3 |
| 灰 | #8A8F95 | 58, 0, −1 |
| 黑 | #14181C | 10, 0, 0 |
| 金 | #D4A017 | 72, 12, 62 |

判定规则：

```
1) 归一化：先做白平衡/灰卡校正 → 再转 Lab
2) 低饱和 + 高 L → 走"白/灰/银"专用判据（S<0.12 且 L>85→白；L∈[70,85]→银/米白；L<18→黑）
   ★ 白/灰/银/黑单独判，不参与彩色 ΔE 竞争（否则深蓝常被判成黑）
3) 彩色：最近邻 ΔE2000
   conf    = clamp(1 − ΔE/25, 0, 1)
   ΔE ≤ 8   → 高置信，正常播报
   8 < ΔE ≤ 18 → 低置信，播报 + 标记"疑似"（如 橙/棕、蓝/青、粉/红 易混）
   ΔE > 18  → "未识别色"，不播报，进人工复核队列
4) 双候选接近（ΔE₂ − ΔE₁ < 2）→ 输出 "X（疑似 Y）"，便于现场确认
```

### 3.11 输出与存档

* 画面：**旋转矩形框**（`cv2.minAreaRect`，贴合长方形）+ 中文标签 `红 #E02020 0.96`（沿用已有 `_font/_draw` 中文绘制管线）。
* 存档三件套（每次触发）：
  * `captures/YYYYMMDD_HHMMSS_full.jpg`（带框原图）
  * `captures/.../crop.jpg`（物体裁剪图）
  * `captures/.../mask.png`（掩膜，便于追溯）
  * `records.jsonl`（一行一条：时间、颜色、Lab、Hex、置信度、框坐标、图片路径、耗时）

### 3.12 记录与播报

* **记录**：后端新表 `vision_records`（★新建表，不改旧表）+ 事件总线 `emit("vision", ...)` → WS 推送 + 审计。
* **播报**：前端 **Web Speech API**（`SpeechSynthesisUtterance`，`lang=zh-CN`，离线可用、零依赖、可控音量/开关）；
  现场要"音柱"时再加后端方案：`pyttsx3`(SAPI5) 或 `edge-tts`(需联网)，做成可选。
* **去重**：同一事件只播一次；连续同色可设"重复播报间隔 ≥ 3s"。

## 4. 工业现场抗干扰清单（这部分决定能不能长期稳定跑）

| 干扰 | 症状 | 对策 |
|---|---|---|
| LED 频闪 | 颜色周期性漂移 | 直流稳压光源；或曝光设为 **10ms 整数倍**（消 50Hz）；禁用自动曝光/自动白平衡（**锁定**） |
| 自动白平衡漂移 | 同一物体前后判成两色 | 相机端**关闭 AWB**，用固定增益 + 灰卡标定 |
| 塑料/金属高光 | 主色被白点拉偏 | 掩膜剔高光（§3.7）+ 环形光 + 漫射罩 + 偏振片（金属必上） |
| 黑色/深蓝/深棕混淆 | 深色互判 | 深色单独判定 + 提高曝光 + 双候选提示 |
| 白色/银色/米白混淆 | 浅色互判 | 低饱和专用判据 + 可合并为"白/银"一类（若现场不区分） |
| 背景与物体同色 | 抠不出来 | 换成**中灰 18% 背景板**（与所有色都有反差） |
| 手/人误入 | 误检 | ROI 限制 + 面积阈值 + 必须"静止"才判 |
| 传送带振动 | 稳定判据不过 | 稳定阈值放宽到 5px；或加编码器/到位信号 |
| 批次色差 | 同"红"两种料判成两色 | 色卡按**物料批次**分组；支持"同一中文名下多个 Lab 参考" |
| 透明/半透物体 | 颜色被背景污染 | 背景板对比色 + 背光/透射光方案（需现场确认） |

## 5. 标定（把"能跑"变成"能放心跑"）

三种标定，建议**全做**：

1. **灰卡标定**（30 秒）：放灰卡 → 点"标定白平衡" → 算通道增益 → 存 `calib.json`。
2. **实物色卡标定**（5~10 分钟，**最重要**）：每色真实物体放 ROI 中央 → 点"采集为 XX 色" → 自动存 Lab 参考（可存多个样本，取中位）。
3. **ColorChecker 24 色**（可选，15 分钟）：拟合 3×3 校正矩阵，进一步压 ΔE。

标定后自动生成**验收报告**：每色重拍一次，输出 ΔE 与混淆矩阵，ΔE 全部 < 8 才提示"可投产"。

## 6. 开源 / 现成组件取舍（你要的"可以用开源项目"）

| 能力 | 选型 | 理由 |
|---|---|---|
| 分割/形态学/轮廓/矩形 | **OpenCV 自带**（`createBackgroundSubtractorMOG2`、`morphologyEx`、`minAreaRect`） | 已在 venv，快、可控、无需训练 |
| 主色聚类 | **OpenCV `cv2.kmeans`** | 零依赖、够快 |
| 色差 ΔE2000 | **自写 numpy（~30 行）** | 离线可部署；`colour-science` 亦可但多一个依赖 |
| 实例分割（可选） | **ultralytics YOLOv8-seg** | 已在 venv；仅背景复杂/粘连时启用 |
| 标注绘制 | 沿用项目自有 `_draw`（PIL 中文字体） | 不引入 supervision 等库 |
| 语音播报 | **Web Speech API**（前端）为主；`pyttsx3`/SAPI 可选 | 零成本、离线、中文 |
| 颜色命名/色卡标准 | 参考 X-Rite ColorChecker、CIE Lab 标准值 | 初值来源，现场覆盖 |

> 一句话：**OpenCV 打主力，YOLO 当备胎，色卡标定决定上限。**

## 7. 性能预算（1 秒停留绰绰有余）

| 环节 | 耗时（ROI 600×400） |
|---|---|
| 背景差分 + 形态学 | ~4 ms |
| 轮廓 + 矩形筛选 | ~1 ms |
| 掩膜净化 + 采样 | ~2 ms |
| kmeans（5000 点, k=3） | ~3 ms |
| ΔE2000（18 类） | ~0.1 ms |
| 绘制 + 存档（仅触发帧） | ~15 ms（JPEG 编码） |
| **单帧合计** | **≈ 10 ms（100fps 余量）** |
| 稳定判定 3 帧 | ≈ 30~100 ms |
| **端到端延迟** | **< 300 ms ≪ 1000 ms 停留** |

## 11. 我的额外建议（超出你提的需求，但现场一定会用到）

1. **统计看板**：各颜色计数、占比、当日产量、节拍（件/分钟）—— 颜色分拣现场最常问的就是"今天红的有多少"。
2. **NG 与复核队列**：低置信/未识别进"待复核"，人工点一下即归类并**自动把该样本并入色卡**（自学习）。
3. **双相机/多角度（可选）**：若物体顶面与侧面不同色，需要两路判定再融合。
4. **掉线自愈**：相机断流自动重连（已有 `/reconnect`），视觉线程不崩。
5. **节拍保护**：若物体停留 < 300ms（比预期快），自动降级为"快速模式"（跳过多帧稳定，2 帧即判）。
6. **权限**：标定与规则配置需管理员令牌（沿用 `require_admin`），检测与查看公开。
7. **数据留痕**：每次判定都存**原图 + 掩膜 + Lab 数值**，出现争议可回溯 —— 这是工业现场最值钱的东西。

## 12. 需要你拍板的 5 件事

1. **MVP 先跑还是一次做全？**（我建议先 P1–P3，看到真实画面再上标定与联动）
2. **颜色清单**：先按内置 18 类，还是只保留你们实际用的几种（越准）？
3. **背景板**：能否加装中灰背景板？（性价比最高的一项改动）
4. **光源**：现在是什么灯？能否锁定曝光/白平衡（关自动）？
5. **播报**：浏览器语音够用吗，还是必须现场音柱？
