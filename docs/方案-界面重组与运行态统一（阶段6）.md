**四条设计原则**

1. **顶栏只放"去哪"，底栏只放"现在怎样"。** 导航在上，运行态在下 —— 这是工业 HMI 的通行分法（SCADA/示教器一致）。
2. **底栏左侧恒定、右侧操作。** 状态灯（只读）在左，控制按钮（可写）在右，视觉上"看"和"动手"分开，避免误触。
3. **常态显示 = 三个灯；异常显示 = 一条引导条。** 三个状态灯**永远在**（这是 R9 的核心）；引导条**有未通过项才出现**，且只报最高优先级的一条，不刷屏。
4. **视觉顺序按"会不会伤人"排**：围栏 → 机器人链路 → 摄像头 → 示教器档位。围栏最左，因为它唯一能拦住物理动作。

## 3. 分项设计（本次落地主体）

### 3.1 R8 · `#control-zone` 从顶栏移到底栏右侧

**做法**：`<div id="control-zone">` 整块从 `#topbar` 内移到 `#bottom-zone` 末尾。

**为什么放在最右**：底栏顺序是 `安全片 → 状态灯 → 引导条(flex:1) → 控制区`。引导条吃满中间剩余宽度，控制区自然被顶到最右；缩窄窗口时 `flex-wrap` 换行，控制区还是最后一个（右下角），不会插到状态灯中间。

**样式调整**（`index.html`）：
- 顶栏版本有 `border-left` 分隔线（与 tabs 分割），移到底栏后 **删除该分割线**，改为 `border-left: 1px solid var(--line)` 保留 —— 但把它左边换成引导条，分隔线仍有意义，保留。
- 高度对齐：底栏是 `padding: 5px` 的 flex 行，按钮高度由 `padding: 7px 14px` 决定；状态灯 `padding: 6px 12px`。两者高度差 2px，用 `align-items: center` 吸收，视觉上是"一条线上的两颗不同宽度的胶囊"。

**风险与对策**：窄屏（≤720px）时控制区文字会撑破底栏 → 沿用既有断点规则：`.ctrl-badge span, .ctrl-request span { display: none }`，只留图标。

### 3.2 R9 · 底栏三盏常驻状态灯（本方案新增的核心件）

**目标**：`机器人链路 / 摄像头 / 示教器档位` 三个状态**任何情况下都显示**。

**数据契约**：`GET /api/system/guide` 新增 `links` 段（与 `checks` 平级）。

```jsonc
"links": {
  "robot": {
    "ok": false, "state": "sim|real|offline|sim_forced",
    "level": "ok|warn|err", "label": "模拟数据", "detail": "…",
    "host": "192.168.1.12", "port": 502,
    "connected": false, "simulated": true, "simulate": "auto"   // simulate = always|never|auto
  },
  "camera": {
    "ok": true, "state": "ready|opening|idle|error|down",
    "level": "ok|warn|err", "label": "相机已连接",
    "detail": "MV-CU120-10GM SN xxx 192.168.1.51 4024x3036 30 fps",
    "base": "http://127.0.0.1:8100", "port": "8100",
    "opened": true, "device": "MV-CU120-10GM · xxxx", "ip": "192.168.1.51",
    "fps": 30, "resolution": "4024x3036", "error": ""
  },
  "run_mode": {                     // 见 §3.3
    "mode": "T1|T2|AUTO|REMOTE|''", "confirmed": true, "stale": false,
    "label": "T1 手动低速", "desc": "…", "joggable": true,
    "level": "ok|warn|err", "actor": "admin", "age_sec": 12
  }
}
```

**状态机（每一档都要有确定文案与颜色，不许出现"未知"）**

| 灯 | state | 触发条件 | 颜色 | 文案 |
|---|---|---|---|---|
| 机器人 | `real` | `connected && !simulated` | 绿 | 真实链路 |
| | `sim_forced` | `simulated && simulate=="always"` | 黄 | 强制模拟（配置项） |
| | `sim` | `simulated && simulate!="always"` | 红 | 模拟数据（真机掉线降级） |
| | `offline` | `!connected && !simulated` | 红 | 未连接 |
| 摄像头 | `ready` | 相机服务 200 且 `opened` | 绿 | 相机已连接 |
| | `opening` | `opening == true` | 黄 | 正在打开 |
| | `idle` | 服务通、相机未开 | 黄 | 相机未打开 |
| | `error` | 服务通、`error` 非空 | 红 | 相机未连接 |
| | `down` | 服务不可达 / `status != 200` | 黄 | 相机服务未启动 |
| 示教器 | `ok` | 已声明且该档允许手动点动（T1/T2） | 绿 | `T1 手动低速` |
| | `err` | 已声明且该档禁止点动（AUTO/REMOTE） | 红 | `AUTO 自动` |
| | `warn` | 未声明 / 声明已过期 | 黄 | 未确认 |

> **★ 摄像头"服务未启动"给黄色不给红色**：它是**部署状态**不是**故障**（跑没跑 `run.bat camera`），
> 给红色会和"相机网线掉了"混淆，现场会去查网线。黄色 + `detail` 里给启动命令。
>
> **★ `sim_forced` 与 `sim` 必须分开**：`simulate=always` 是**你主动选的**（配置项），
> 给红色等于天天报警；`simulate=auto` 下掉线降级才是真故障，必须红。这两者混在一起是最容易埋没真故障的地方。

**前端实现**
- 新增 `src/linkview.js`：**纯函数** `robotPill(links) / cameraPill(links) / modePill(links)` → `{key,icon,label,value,title,tone}`。
  抽成纯函数是为了能在 node 里把**每一个状态**的最终文案与色号断言钉死（见 §8，这是我的既有铁律：
  "按状态取色必须 headless 断言，否则缺配置时会静默回退成绿色"）。
- 新增 `components/StatusStrip.vue`：只负责渲染三颗胶囊 + 展开详情 popover。
- 新增 `stores/link.js`：**唯一**的 `/system/guide` 轮询者（5 秒），`GuideBar` 改为消费它。
  ★ 现状是 `GuideBar` 自己 `setInterval` 拉 `/guide`；再加一个轮询者就有两路请求、两份状态，
  迟早出现"底栏灯是绿的、引导条还是红的"。必须收敛成一个源。

**点击行为**
- 机器人灯 → 展开：`host:port`、`simulate` 配置值、一键「重新连接」（需令牌）。
- 摄像头灯 → 展开：设备型号/序列号/IP/分辨率/fps、失败原因、一键「重连相机」「打开相机」。
- 示教器灯 → 展开：四档选择器（见 §3.3）。

### 3.3 R9/R10 · 示教器档位声明（L1）

**问题**：模式开关是示教器上的**硬件旋钮**。当前 Modbus 点位表（reg10-21，FC3）**没有模式寄存器** ——
软件读不到。R9 要求"不管有没有 AUTO 都要显示"，但"显示什么"没有数据源。

**方案**：改为 **显式声明 + 越权拦截**，四个档位全部可声明，全部可显示。

| 档位 | 官方语义 | 手动点动 |
|---|---|---|
| T1 | 手动低速（示教） | ✅ 可用，TCP ≤ 50 mm/s |
| T2 | 手动高速 | ✅ 可用，禁止进围栏内 |
| AUTO | 自动运行 | ❌ 控制器拒绝手动点动 |
| REMOTE | 远程/上位机控制 | ❌ 不可用 |

**四条硬规则**
1. **只拦"已声明为 AUTO/REMOTE"这一种确定危险的情形**；未声明时**放行**，只记一条 warn 事件。
   理由：`simulate` 联调、相机调试、标定这些都不需要真机，堵死等于不可用。这与围栏互锁
   "未上报则放行但记 `control.interlock_absent`" 是**同一策略**，一致性优先。
2. **声明不持久化**。后端重启 → 回到"未确认"。理由：重启与旋钮位置无关，拿旧声明放行等于凭空假设。
3. **声明有效期 2 小时**，超时视为未确认（`stale=true`）。防止"昨天的声明给今天授权"。
4. **档位提示恒为 `level=info`**，不参与主提示条排序。
   ★ 否则后端一重启，引导条主提示永远是"档位未声明"，把真正的故障挤下去 —— 这是典型的"狼来了"失效。

**接口**
```
GET    /api/control/run-mode    当前声明（含四档选项与说明）     需令牌
POST   /api/control/run-mode    {mode, note} 声明                需令牌
DELETE /api/control/run-mode    撤销声明                         需令牌
```
声明/撤销都进事件总线（`control.run_mode` / `control.run_mode_clear`），审计可查"谁在什么时候把档位声明成了 AUTO"。

### 3.4 R10/R11 · 点动模式与坐标系（落地入口）

详细设计沿用 `方案-示教器坐标系与点动模式适配.md`，此处只钉**接口与行为**：

- **两种模式都必须保留、可互相切换**（你的明确要求）。切换只改"按什么方向动"，**不改速度上限、不改安全关**。
- `POST /api/control/jog/step|start` 新增可选字段：`frame`（`joint|base|tool|user`，缺省 `joint`）、
  `user_frame`（wobj id）、`slow`（慢速 ÷10）。**不传 `frame` 时行为与今天逐字节一致** —— 向后兼容是硬要求，前端旧代码/脚本不能因为这次升级而改变语义。
- 直角系求解：`base/user` 对 `fk_matrix(q)` **左乘**坐标变换，`tool` **右乘**；IK 初值必须取**当前关节角**
  （多初值会在点动中途跳到另一个构型，人眼看到的是"机器人自己甩了一下"）。
- **速度缩放**：解出的 `Δq` 按比例缩到没有任何轴超过 `max_speed_dps`，响应里回 `speed_scale`，
  前端据此显示"已限速 40%"。接近奇异点时先折半重试再限速，仍不收敛则拒绝并提示**切回关节系**。
- 单位**按轴**而非按坐标系：直角系 1/2/3 是 mm、4/5/6 是 deg；关节系恒为 deg。
- 轴号沿用官方：`1±=X 2±=Y 3±=Z 4±=A(绕Z) 5±=B(绕Y) 6±=C(绕X)`。
- `wobj0 ≡ 机器人坐标系`（官方明文），因此 `base` 与 `wobj0` **共用同一条求解路径**，不写两份。

### 3.6 R13 · 运行日志可读性

**两个真问题**（不是"数字不够大"）：
1. `.side` 是 `display:flex; flex-direction:column`，`.card` 是它的 flex 子项，默认 `flex-shrink:1`
   → 内容超高时**所有卡片一起被压扁**，处在最下面的「运行日志」被压得只剩两三行。
   这正是你看到"日志太短"的根因，不是 `max-height` 设小了。
2. `.run-log` 的 `overflow-y:auto` 在 Windows 深色主题下**滚动条几乎不可见**，你看到的是"没有滚动条"。

**修法**
- `.side > * { flex: none; }` —— 卡片保持自然高度，改由 `.side` 自己滚动（滚动容器只该有一个）。
- `.run-log { height: 148px; flex: none; line-height: 1.5; }` —— 148px 扣掉 12px 内边距 ≈ 7 行，**稳超 5~6 行**。
- **全局细滚动条**（`::-webkit-scrollbar` 8px，滑块 `--line` 色、悬停 `--accent`）：`.side / .run-log / .rec-list / .ev-list` 统一，让"可滚动"这件事在深色主题下看得见。
- **新增日志自动滚到底**（贴底时才自动滚，用户手动上翻时不打扰）。

## 5. 安全设计（不变式，落地时必须逐条守住）

| 不变式 | 违反后果 | 守住方式 |
|---|---|---|
| 安全关**只增不减** | 新功能绕过急停/围栏 | 点动、下发共用 `_block_reason()`；新增判定只能往里加 |
| 档位**只拦确定危险** | 联调不可用 | 未声明放行 + 留痕；仅 AUTO/REMOTE 拒 |
| 声明**不持久化** | 拿旧值误放行 | 进程内状态，重启即失效 |
| 档位提示**不抢主提示条** | 真故障被淹没 | `level` 恒 `info` |
| 向后兼容 | 老脚本语义漂移 | 不传 `frame` ≡ 今天的行为 |
| 视野**不因状态条变化而跳动** | 3D 视口高度抖动 | 状态灯恒定占位（比引导条更稳），底栏固定在 `#main` 之后 |
| 取色**必走查表 + 断言** | 缺配置静默回退绿色 | `linkview.js` 纯函数 + 逐状态断言 |
