# 控制器 Modbus 寄存器表与控制权限（实测确认）

> 对象：FIT / EFORT **ER8-700H + RP-2 控制器**，`192.168.1.12:502`，从站号 `1`
> 来源：**实机验证**（不是手册抄录）。参考实现见私有仓库
> `YLJ109/efort_panel_pyqt6`（PyQt6 远程控制台），本表与其 `efort_client.py` 逐项对齐，
> 并在本项目现场复测通过（2026-09-23）。
> 只读勘察工具：`scripts/reg_survey.py`（全 FC3，不写任何寄存器）。

## 1. 结论摘要

| 项 | 值 |
|---|---|
| 协议 | Modbus TCP，端口固定 **502**，从站号 **1**（0 无应答），PC 作主站 |
| FLOAT 编码 | 占 2 寄存器，**字序 CDAB**（低字在前） |
| 关节角读取 | `40011~40022`（0 基址 `10..21`），**一次读 32 个寄存器（地址 0 起）最稳** |
| ★ 让关节动的唯一路径 | 控制器上跑一个常驻程序 → PC 写目标角 + 置触发位 |
| ★ Modbus **没有**关节级/点动原生指令 | 想动轴只能"加载并运行控制器上的程序" |

### 地址换算
手册写 `4xxxx`，多数库按 **0 基址**收发 → 本文同时给出两种写法，**代码里用 0 基址**。

| 手册（4xxxx） | 0 基址 | 含义 |
|---|---|---|
| `40001` | `0` | 状态位（见 2.1） |
| `40003` | `2` | 运行速度（%） |
| `40004` / `40005` | `3` / `4` | 报警码 1 / 2 |
| `40006` | `5` | **当前程序号** |
| `40011~40022` | `10..21` | **J1~J6 关节角（FLOAT，CDAB）** |
| `40101` | `100` | **指令位**（见 2.2） |
| `40103` | `102` | 速度设定 |
| `40104` | `103` | 目标程序号 |
| `40035` | `34` | 机器人→PC 用户位区，**Bit0 = 点动完成回执** |
| `40135` | `134` | PC→机器人 用户位区，**Bit0 = 点动触发** |
| `40139~40144` | `138..143` | PC→机器人 **J1~J6 目标绝对角 ×100（int16）** |
| `40301~40400` | `300..399` | 用户可读可写区（现为全 0） |

## 2. 状态位与命令字

### 2.1 状态位（读 `40001`）
`Bit0` 手动 · `Bit1` 自动 · `Bit2` 远程 · `Bit3` 伺服 · `Bit4` 报警 ·
`Bit5` 急停 · `Bit6` 程序运行 · `Bit11` 程序加载 · `Bit12` 伺服就绪

### 2.2 指令位（写 `40101`）
`Bit0` 上下伺服 · `Bit1` 运行 · `Bit2` 停止 · `Bit3` 清报警 · `Bit4` 加载 ·
`Bit12` 伺服使能 · `Bit13` 取消使能

### 2.3 命令字（**必须"同沿"单条写入，且始终保留 Bit0 + Bit12**）

| 动作 | 值 |
|---|---|
| 伺服上电 | `0x1001` |
| 加载程序 | `0x1011` |
| 运行程序 | `0x1013` |
| 停止 | `0x1005` |
| 清报警 | `0x1009` |
| 取消使能 | `0x2000` |
| 全清 | `0x0000` |

- **重新吸合序列**：`0x0000` → **等 0.6s** → `0x1001`（吸合延迟实测 ≈0.55s；只等 0.3s 吸不上）。
- 写 `0x0000` 常**不回正常应答但已生效** → 代码必须容忍异常。
- `FC6` 的响应体是 `[fc][addr_hi][addr_lo][val_hi][val_lo]` → 回显值在 **`body[3:5]`**，不是 `[2:4]`。

## 3. ★ 点动链路（= "获取控制权限"）

控制器上必须有一个**常驻点动服务程序**（本项目现场号 = **200**，名 `JOGSVC`）：

```
WHILE true DO
    fidbus.mtcp_wo_b[0] := false;            (* 清回执 → 40035.Bit0 = 0 *)
    WAIT(fidbus.mtcp_ro_b[0]);               (* ★ 等【读区】触发 → 40135.Bit0 *)
    MJOINT(POINTJ(fidbus.mtcp_ro_i[0]/100.0, ... ,fidbus.mtcp_ro_i[5]/100.0),
           v100perc, fine, tool0);
    fidbus.mtcp_wo_b[0] := true;             (* 置回执 → 40035.Bit0 = 1 *)
    WAIT(NOT fidbus.mtcp_ro_b[0]);           (* ★ 等上位机撤触发，防同一发执行两遍 *)
END_WHILE;
```

| 方向 | 寄存器 | 程序侧变量 |
|---|---|---|
| PC → 机器人 | `40135` Bit0（触发，电平） | `fidbus.mtcp_ro_b[0]` |
| PC → 机器人 | `40139~40144`（J1~J6 绝对角 ×100） | `fidbus.mtcp_ro_i[0..5]` |
| 机器人 → PC | `40035` Bit0（到位回执） | `fidbus.mtcp_wo_b[0]` |

> ⚠ **`ro_*` = PC 写、程序读；`wo_*` = 程序写、PC 读。**
> **`WAIT` 必须等读区 `ro_*`**。写成写区就等于"自己等自己刚置的值" → 程序**卡死在 WAIT**。
> 现场特征：运行位常亮、`40035` 完成位恒 0、机器人一动不动。

### 3.1 上位机侧点动时序（每一步都别省）
1. **防冲预置**：把 `40139~44` 写成**机器人当前实际角**。这样即使程序漏写 WAIT，
   MJOINT 的目标也只是"现在这个姿态" → **零位移**。
2. 写 6 个目标绝对角（`FC6 × 6`）。
3. **回读校验** `40139~44` 与目标一致。
4. **静置 ≥0.15s** —— 等控制器把 Modbus 读区抄进程序变量空间。
5. 置 `40135.Bit0 = 1` 触发。
6. 轮询 `40035.Bit0` 等到位回执。
7. **撤触发**（写 `40135 = 0`）—— 程序回到 WAIT，等下一发。

> ★ **第 3~4 步是硬要求**。写完立刻触发会命中竞态：程序被放行时读到的还是**上一轮旧目标角**
> （= 当前角）→ 机器人不动，但**照常回完成位**。
> 判别特征：**完成位 <0.1s 就回 + 零位移**。真动作绝不可能是 0.1s。

### 3.2 点动速度
由 **`40103`** 控制（不是程序里的 `v100perc`）：`40103 = 5% → ≈1.3°/s`；`100% → ≈60~90°/s`。
`zone = fine` 每步整定到位，实测启动延迟 `0.09~0.13s`。

## 4. 一级就绪流程（"一键就绪"）

1. 连接
2. 有报警 → `0x1009` 清报警（+0.4s 后若伺服掉了就重吸合）
3. 伺服未上电 → `0x1001`（等 ≥0.55s）；不行为 → `0x0000` → 0.6s → `0x1001`
4. **必须在【自动】模式** —— 手动(T1/T2)下**外部 Modbus 指令一律被忽略**
5. 写 `40104 = 程序号` → `0x1011` 加载 → 等 `Bit11` 程序加载位置位（≈0.6s）
6. `0x1013` 运行 → 程序停在 `WAIT` 挂起（**运行位常亮是正常的**）→ 此时点动通道已就绪

---

## 5. 硬规则（全部踩过）

1. **先加载成功，才允许触发运行**。对不存在的程序号发运行 → 立刻报警 **5005**。
2. **必须【自动】模式**；手动模式下外部指令被忽略，表现是"程序在、就是不动"。
3. **"远程位（Bit2）"不是门槛** —— 已证伪，不必去切。
4. **"假 5005"**：示教器停在**文件管理器/编辑程序**界面时，远程加载会被临时拒绝，
   照样回 `5005 / 代码 -3`，但程序其实存在 ⇒ **先让示教器退出文件界面再复测**。
5. **加载前不要发停止（`0x1005`）** —— 实测停止之后控制器会拒绝加载。加载前只需清报警 + 撤触发。
6. **残留报警会堵住加载** —— 5005 挂着时加载必失败，先 `0x1009` 清。
7. 加载失败会**抖动**（同一批程序同一秒内可能假失败）→ **多轮重试**是必须的。
8. **进过示教器的程序编辑态 → 伺服会被下使能** → 走一次重吸合再判断。

## 6. 报警码

| 码 | 含义 | 处理 |
|---|---|---|
| **1812** | **安全门报警**（不是驱动器报警） | 检查安全门/安全回路；`0x1009` 清 |
| **3909** | 示教器未连接（bcc 客户端通讯断开/重连超时） | 检查示教器线缆/电源/急停，恢复连接后重试「一键就绪」 |
| **5005** | 远程加载程序错误（代码 −3 = 当前加载的程序不存在） | 确认程序号；排掉"假 5005"（含 3909 示教器未连接） |
| **4902** | XPL 文件 API 错误（文件在，但内容/格式坏） | 重做程序文件（用菜单点选录入，别文本手打） |
| 段位 | 1~999 系统 / 1800~1999 用户 Major / 3900~3999 Minor / 4900~4999 Warning | |

`0x1009` 清报警约 **0.12s** 生效。

## 7. 本项目的现状（2026-09-23 实测）

- ✅ **控制权限已取得**：清掉 1812 安全门报警（清后未复现 ⇒ 安全回路当时满足）→ 伺服上电 →
  程序 **200 加载 0.60s → 运行位置起 0.46s** → 停在 WAIT 挂起。
- ✅ **J6 实机点动验证通过**：`124.30° → 125.30°`，命令 `+1.00°`、**实测 `+1.000°`（误差 0）**，
  其他 5 轴位移 `0.001°`，报警 `0/0`，启动延迟 `0.62s`，运动段 `0.56°/s`（`40103 = 5%`），全程 `2.39s`。
- ✅ **`138..143` 的语义已确认**（早先的勘察笔记把它当成"第二路关节角读数"，**这是错的**）：
  它是**点动目标角寄存器**（`fidbus.mtcp_ro_i[0..5]`），写什么机器人就往哪走。
  之所以它读出来**恰好等于当前位姿**，是因为做过**防冲预置**（把目标写成当前角）。
  ⚠ 因此"两路读数交叉核对"只在**刚做完防冲预置之后**才成立；平时两者是
  "目标 vs 实际"，差多少取决于最后一次点动了多少。
  真正可用于判断"是否读到真机"的，是 `10..21` 的 FLOAT 路本身是否在变。

### ★★ 与后端现有实现的冲突（重要）
`backend/app/services/modbus.py::write_target` 现在做的是
**`FC16` 往地址 `30` 写 12 个 float**（`robot.yaml: motion.write_base_addr = 30`）。
**这条路径是错的**，实测：
- 地址 `30..41` 可读且**恒为 0**，不是目标关节角区；
- 真实下发路径是**逐寄存器 `FC6` 写 `40139~44` + 置 `40135.Bit0`**（第 3 节）。

因此 `motion.write_base_addr` / `write_speed_addr` / `estop_addr` 这三个 TODO 应该**删掉**，
换成第 1 节的确认地址表 + 一条"点动通道"实现。
**在改完之前，`motion.real_write` 必须保持 `false`**（现状即如此）。
