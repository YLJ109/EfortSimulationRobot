# 真机点动/执行跑不动排障：点动服务程序缺失

## 现象
- 一键就绪卡在 `程序运行位未置位，请检查程序状态`（日志续 `运行 2.5s 内未置位`）
- 真下发 run-file 第一步就回 `点动完成位 4.0s 内未置位（检查点动服务程序是否在 WAIT 挂起）`
- 错误定位里看得到 `程序=200 加载=1 运行=0`

## 根因（2026-09-23 现场 + 开源项目 efort_panel_pyqt6 实测确认）
**控制器上根本没有 200 号点动服务程序。** 扫描 1~600，只有 410、411 存在。
而我们的后端 `config/robot.yaml` 把 `motion.jog.service_program` 默认设成 `200`。
于是后端把 200 当点动服务去加载/运行，可 200 号不存在（或不是能回执的常驻点动程序），
触发位写了没人接 → 完成位永久不置 → 单轴点动 / 程序下发全都不动。

> 这是该开源项目也踩过的同一个坑：旧版硬编码"点动程序=200"，现场没有 → 反复白报 5005。
> 正确做法是 **在示教器上把点动服务程序建出来**，再把它的号配给后端。

## 为什么必须有点动服务程序
Modbus **没有**原生点动指令（40101 指令位已穷举到 Bit13，无关节级指令）。
上位机只能用"控制器上跑一个常驻程序来回执"的方式：
```
上位机写目标角 40139~44(×100) → 置触发位 40135.Bit0
   → 常驻程序 WAIT 读到触发 → 运动(MJOINT) 走目标角
   → 上位机写完成位 40035.Bit0 → 撤触发 → 程序回 WAIT
```
这个常驻程序就叫**点动服务程序**。它必须有、必须在示教器上建好。

## 一、在示教器上建点动服务程序（官方推荐，全点选）
1. 任务栏 →【程序】→ 程序界面（需编程权限，登录密码 `999999`）
2. 左侧【指令栏】逐个加入列 5~6 条到【程序树】
3. 每条设好参数（变量选【选择变量】，表达式进【编辑】）
4. 点任务栏【保存】（官方："如不保存到文件修改是暂时的"）

按顺序插入（等价逻辑见下方代码）：

| # | 指令类型 | 内容 |
|---|---|---|
| ① | 循环/Loop → WHILE | 条件保持默认 `true`（ENDWHILE 自动补） |
| ② | 基本 → 赋值 `:=` | 变量 `fidbus.mtcp_wo_b[0]` = `false` |
| ③ | 基本 → WAIT | 条件【编辑】= `fidbus.mtcp_ro_b[0]` （★ 读区！勿用 wo 写区） |
| ④ | 运动 → MJOINT | 速度 v100perc / fine / tool0 / wobj0；目标点 POINTJ 写 6 个表达式 |
| ⑤ | 基本 → 赋值 `:=` | 变量 `fidbus.mtcp_wo_b[0]` = `true` |
| ⑥ | 基本 → WAIT | 条件 = `NOT fidbus.mtcp_ro_b[0]`（等上位机撤触发，防重复执行） |

第 ④ 条 POINTJ 的 6 个表达式：
```
fidbus.mtcp_ro_i[0]/100   …  fidbus.mtcp_ro_i[5]/100
```

## 二、等价代码（对照用）
```
┌ 声明 6 个 LREAL 程序变量：j1 j2 j3 j4 j5 j6
WHILE true DO
    fidbus.mtcp_wo_b[0] := false;
    WAIT(fidbus.mtcp_ro_b[0]);
    j1 := fidbus.mtcp_ro_i[0]/100.0;
    ...  j6 := fidbus.mtcp_ro_i[5]/100.0;
    MJOINT(POINTJ(j1,j2,j3,j4,j5,j6), v100perc, fine, tool0);
    fidbus.mtcp_wo_b[0] := true;
    WAIT(NOT fidbus.mtcp_ro_b[0]);
END_WHILE;
```

## 三、建好后配置后端
1. 记住这个程序在示教器上的**程序号**（例如建为 300）
2. 编辑 `config/robot.yaml`：
   ```yaml
   motion:
     jog:
       service_program: 300     # ← 改成你建的点动服务程序号
   ```
3. **重启后端**
4. 页面重新登录（口令见 `.env`）→【一键就绪】→ 它加载并挂起于 WAIT
5. 点 J1~J6 单轴 ±1° 验证

## 四、确认控制器上实际有哪些程序号
运行只读扫描（backend 目录下）：
```
Some调用(backend\.venv\Scripts\python.exe) tools/scan_programs.py 1 300
```
它只「尝试加载 + 读加载位/报警」，结束后自动还原程序号、清报警，**绝不运行、不运动**。
若看到你的点动服务程序号在存在列表里，就说明配对了。

## 五、"运行了但点了不动"最高频坑（2026-09-23）
症状：运行位亮、完成位恒 0、零位移 → 程序**卡死在 WAIT 那行，触发没被接住**。
原因几乎总是：WAIT 条件变量选错。
- ✅ 正确：`fidbus.mtcp_ro_b[0]` = 读区 = 40135.Bit0（上位机写、机器人读）
- ❌ 错误：`fidbus.mtcp_wo_b[0]` = 写区 = 40035（机器人写、上位机读）——
  程序第一句自己把它置 false，永远等不到
核对：示教器打开程序看【当前执行行】是否停在 WAIT；改完必须点【保存】。
