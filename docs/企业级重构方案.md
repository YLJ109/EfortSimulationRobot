# EFORT Web Monitoring 企业级重构方案

> 目标：无 bug、完整、可维护、可测试、生产可用的企业级全栈监控系统。
> 原则：先方案后执行，一次到位，不中途卡住。所有改动保持既有功能 100% 兼容。

## 三、前端 Vue 迁移方案

**技术选型**：Vue 3（`<script setup>` + Composition API）+ Pinia（状态）+ Vite（构建，加 `@vitejs/plugin-vue`）。
**不引入 Vue Router**：监控应用 4 个 Tab 是并列常驻视图，用 `v-show` 保持 3D 场景存活（避免 Three 场景销毁重建），路由无增量价值、徒增复杂度。

**迁移要点**：
1. 三套 `robotModel` 场景（live/sim/rec）由 `useThree` composable 统一管理，复用全局单 `WebGLRenderer`（保留 CONTEXT_LOST 修复）。
2. 实时姿态走 Pinia `robot.latestPose`，`RealMonitor` 内 watch 驱动模型 + HUD。
3. 录制引擎（录制/回放/CRUD/导入导出）迁入 `recording` store。
4. 相机轮询/YOLO 配置迁入 `camera` store，MJPEG 流离开视图时断开（保留省资源逻辑）。
5. 键盘控制、指令预演（IK）迁入 `SimMonitor.vue` 内部。
6. `index.html` 仅保留全局样式与 Tab 骨架，业务样式迁入各组件 `<style scoped>`。

## 四、后端企业级改造方案

1. **统一异常处理**：`core/exceptions.py` 定义 `AppError`（含错误码），`middleware.py` 捕获后返回统一 `{code, message, detail}`；未捕获异常返回 500 + 日志。
2. **依赖注入**：`core/deps.py` 提供 `get_db()`，所有路由用 `Depends(get_db)` 替代裸 `SessionLocal()`。
3. **请求日志中间件**：记录 method/path/status/耗时。
4. **CORS 修复**：`allow_credentials=False`（本项目 WS/API 走同源，无需凭据），或改为读配置的 origin 列表。
5. **response_model 全覆盖**：`schemas/` 补齐 History/Export/Meta/Pose/Recording 等模型。
6. **时间处理**：`datetime.utcnow()` → `datetime.now(timezone.utc)`。
7. **配置生效**：`database.py` 优先读 `config.database.url`。
8. **测试**：`tests/` 用 pytest + httpx TestClient，覆盖 health/meta/pose/recordings CRUD/control preview/kinematics。
9. **requirements 分层**：`requirements.txt`（运行时，锁版本）+ `requirements-dev.txt`（pytest/httpx）。
